# 기존 환경과 연결하는 경계

own-harness의 필수 구성은 Python 표준 라이브러리, Git, 로컬 Codex 훅과 pstack-codex 스킬입니다. 외부 도구의 이름이 문서에 있다는 이유로 설치됐거나 실행됐다고 가정하지 않습니다. 아래 선택 항목은 자동 설치·실행·마이그레이션을 제공하지 않습니다.

## Git과 Codex

진입 지침은 로컬 `AGENTS.override.md`에 관리 블록으로 추가합니다. 제품의 `AGENTS.md`는 수정하지 않습니다. 기존 untracked override의 본문은 보존하며, 추적 중인 override는 충돌로 거절합니다. Codex는 같은 폴더에서 override가 있으면 이를 우선하므로 첫 규칙이 원래 `AGENTS.md`를 읽고 따르도록 안내합니다. [공식 지침 탐색 문서](https://learn.chatgpt.com/docs/agent-configuration/agents-md)

Git wrapper는 기존 훅의 인자·작업 경로·표준 입력을 전달하고 기존 훅의 실패를 유지합니다. 저장소별 commit 규칙·lint·identity 정책은 기존 훅이 계속 담당합니다. own-harness는 일반 Git 작성자 정보와 WORK 전달 상태를 검사하며 제품별 브랜치·티켓 규칙을 추가하지 않습니다.

checkout의 `.codex/hooks.json`에는 기존 항목을 보존하며 `UserPromptSubmit`·`PreToolUse`를 설치된 `pr-guard.py`의 같은 진입점에 연결합니다. 진입점은 WORK 통제 이벤트도 전달합니다. 전역 훅은 바꾸지 않습니다. 여러 설정 계층에서 매칭된 훅이 함께 실행될 수 있으므로 `/hooks`에서 실제 출처를 확인하세요. 동일 계층의 inline TOML 훅과 `hooks.json`도 함께 로드될 수 있습니다. 설치 중 충돌로 판정되면 기존 정의를 검토해 정리해야 합니다. [공식 훅 문서](https://learn.chatgpt.com/docs/hooks), [공식 설정 문서](https://learn.chatgpt.com/docs/config-file/config-advanced)

프로젝트 신뢰와 현재 훅 정의에 대한 신뢰는 별도 조건입니다. 설치기는 둘 다 자동 승인하지 않습니다. 실제 클라이언트·프로젝트에서 검토하고 동작을 확인해야 합니다. 합성 이벤트 fixture는 파서·승인 상태·차단 조건의 회귀 검사이며 실제 Codex 훅 활성화 증명이 아닙니다.

`.codex/config.toml`의 `[memories] use_memories = false`는 해당 프로젝트 계층의 자동 메모리 주입 설정입니다. 이미 주입된 대화 내용을 제거하거나 기존 메모리 파일을 삭제했다고 해석하지 않습니다. 복잡한 TOML, 추적 중인 로컬 설정, 충돌하는 스킬·훅 경로는 설치 전에 해결해야 합니다.

## OKF: 확인된 지식

이미 OKF를 운영한다면 구체적인 조사 질문으로 기존 항목을 검색하고 필요한 내용만 읽습니다. 중요한 결론은 현재 소스·호출자·Git 상태와 다시 대조합니다. WORK에는 이번 작업의 범위·선택·검증을, 기존 지식 저장소에는 검증된 지속적 사실을 둡니다. 도구 명령과 저장 경로는 해당 프로젝트에서 확인하며 이 패키지가 고정하지 않습니다.

OKF가 없으면 소스와 Git으로 조사합니다. 설치나 지식 저장소 생성을 작업의 선행 조건으로 만들지 않습니다. 문서 검사 통과를 제품 동작 검증으로 바꾸지 않습니다.

## Graft: 재생성 가능한 코드 탐색

기존 Graft 결과는 관련 파일과 호출 경로를 좁히는 보조 자료로 사용합니다. 생성 시점·대상 ref를 확인하고 중요한 경로는 현재 소스와 실행 결과로 검증합니다. 그래프는 전체 동적 동작을 보장하지 않습니다.

Graft 결과 전체를 OKF나 WORK로 복제하지 않습니다. Graft가 없거나 오래됐다고 해서 그래프를 자동 생성하지 않으며, 해당 작업에서 필요한지와 기존 실행 절차를 먼저 확인합니다.

## RRSI: 별도의 효율성 평가

이미 RRSI 평가 체계가 있으면 고정한 작업·환경·기준 버전과 결과를 비교합니다. 하네스 변경 뒤에는 그 체계의 재기준 설정 절차와 새 평가 결과를 확인합니다. 이전 결과를 새 runtime의 통과 결과로 재사용하지 않습니다.

합성 평가나 실행 명령의 성공은 실제 pstack 수행·제품 품질·모든 작업의 효율 개선을 증명하지 않습니다. 이 패키지는 RRSI 실행기, 모델 라우터, 자동 평가 스케줄러를 설치하거나 호출하지 않습니다.

## 도메인 자료

프로젝트가 쓰는 승인된 설계·작업 기록·지식 저장소의 소유권을 유지합니다. 처음부터 모든 문서를 읽거나 이전 내부 자료를 공개 패키지에 옮기지 않습니다. 구체적인 질문 → 필요한 부분 조회 → 현재 근거 대조 순서로 사용합니다.
